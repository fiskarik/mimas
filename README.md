# Автособес — каркас локального демо

Next.js + TypeScript, FastAPI, SQLite. Приглашение → проверка устройств → 3 вопроса → Python-код → защита решения → запись и отчёт.

## Запуск на Windows

Нужны Python 3.11+ и Node.js 20.9+. Docker и GPU не нужны.

```powershell
cd C:\MIMAS
powershell -ExecutionPolicy Bypass -File .\setup.ps1
python run_demo.py
```

Открыть http://localhost:3000 в Chrome или Edge. Ключ кабинета: `demo-company`. Создать приглашение и открыть его в другой вкладке. Разрешить камеру и микрофон, отметить согласие, начать интервью. В тестовом режиме отвечать текстом. После завершения вернуться в кабинет, обновить список и открыть отчёт.

Серверы слушают только loopback. Это локальное демо, не публичный сервис. Для другого устройства нужны HTTPS, настройка доступа и доработка авторизации. Не публиковать текущий стенд в интернет.

## Что работает

- Создание персонального приглашения с секретным токеном в URL-фрагменте.
- Пять последовательных этапов; ответы сохраняются до обращения к LLM.
- Тестовый сценарий без ключей: реальные ответы, без искусственных оценок.
- Live-адаптер Groq: структурированная оценка, цитаты сверяются с исходным ответом; вопрос защиты может формироваться по коду.
- Распознавание голосового ответа через Groq при наличии ключа. Расшифровку можно проверить до отправки.
- Озвучивание вопроса средствами браузера по кнопке (зависит от установленных голосов). Piper пока не интегрирован.
- Камера и микрофон записываются MediaRecorder в WebM; фрагменты загружаются с номерами и проверкой повторов.
- Реальные предупреждения при уходе со страницы, потере фокуса, вставке и отключении media tracks.
- Кабинет с ответами, записью, событиями и их временем. В mock-режиме каждый ответ явно «Не оценено».
- Данные и записи в `data/`; доступ к спискам/отчётам/видео защищён ключом компании, кандидат — своим токеном.

## Бесплатный API

Скопировать `.env.example` в `.env`. Ключи хранить только там, не в браузере и не в Git.

```dotenv
AI_MODE=live
GROQ_API_KEY=your_key
GROQ_MODEL=model_available_in_your_free_account
GROQ_STT_MODEL=whisper-large-v3-turbo
COMPANY_KEY=your_local_team_secret
```

Перезапустить `run_demo.py`. Существующие приглашения сохраняют режим, в котором были созданы; для live нужно новое приглашение. Можно оставить `AI_MODE=mock` и добавить только ключ для проверки STT. Доступность регистрации и квот Groq нужно проверить в своём аккаунте. Проект не включает платный тариф и не переключается на него автоматически.

При ошибке LLM ответ остаётся сохранённым, но неоценённым; API позволяет повторить отправку того же ответа для повторной оценки до завершения интервью. Отдельная кнопка повторной оценки в кабинете — следующий этап.

## Честные границы каркаса

- Распознавание отсутствия лица, второго человека, телефона и направления взгляда **не подключено**. Сейчас предупреждения основаны на событиях браузера и устройств; они не доказывают списывание. Браузерные события можно обойти, это не защищённый экзаменационный клиент.
- Python-код **не исполняется**. Кнопки с фиктивными результатами тестов нет. Добавить изолированный runner перед включением запуска; никогда не выполнять код кандидата в процессе API.
- Сейчас обычный редактор textarea; Monaco — последующая замена.
- Запись содержит камеру и микрофон кандидата; звук синтеза браузера может не попасть в неё. Для записи голоса ИИ нужен единый Web Audio mix и серверный TTS.
- Не перезагружать вкладку интервью. Возобновление MediaRecorder после перезагрузки пока не реализовано; незавершённое прохождение остаётся видимым как активное, следует создать новое приглашение.
- Очередь незагруженных фрагментов хранится в памяти вкладки, а не IndexedDB. При обрыве связи не закрывать страницу, повторить загрузку/завершение.
- Финальный WebM собирается из частей одного recorder. На некоторых браузерах длительность/перемотка WebM требуют remux через FFmpeg — отдельная следующая задача. Скачать и воспроизвести запись можно без remux.
- Серверный ключ компании общий для команды, без пользовательских аккаунтов и разделения компаний. Записи не удаляются автоматически: использовать добровольные тестовые прохождения.
- В текущем интерфейсе нет самостоятельного создания произвольных вакансий: один шаблон Python backend.

## Проверки

Проверено при сборке каркаса: 6 API-тестов, production-сборка Next.js и полный браузерный сценарий с синтетической камерой/микрофоном. Автотест создал помеченное тестовое прохождение в локальном кабинете. Проверены предупреждение о вставке, 5 ответов, загрузка частей, воспроизведение WebM и отсутствие горизонтального переполнения на ширине 390px. Живой Groq API без ключа не проверялся.

Браузерный тест: `scripts/smoke-browser.cjs` (требует Playwright и установленный Edge; использует искусственные устройства). Скриншоты проверки сохраняются в `data/qa-browser/`.

```powershell
.\.venv\Scripts\python.exe -m pytest backend -q
cd frontend
npm.cmd run typecheck
npm.cmd run build
```

Перед защитой вручную: проверить реальную камеру и микрофон; пройти все этапы; уйти со вкладки и вставить текст; убедиться в предупреждениях; завершить запись; открыть видео в кабинете. Проверить сохранение при временном отключении API, отказ в разрешениях, отключение камеры и досрочное завершение.

## Следующие задачи команды

1. Прокторинг: MediaPipe Face Detector, затем детектор телефона; устойчивые сигналы, не реакция на один кадр.
2. Голос: проверить Groq Free; Piper на CPU, запись озвучки и микрофона в общую звуковую дорожку.
3. Запись: IndexedDB для очереди, FFmpeg remux, обработка прерванных интервью.
4. Задачи: Monaco и отдельный runner с отключённой сетью, CPU/RAM/PID/time/output лимитами.
5. Контент: проверить вопросы и критерии с Python-разработчиком; сопоставить оценки модели с ручными.

Основные файлы: `backend/app.py`, `frontend/app/page.tsx`, `frontend/app/globals.css`. API-схема: http://127.0.0.1:8000/docs. Контракты уже соединяют интерфейс и сервер, поэтому подсистемы можно дорабатывать независимо.
