# MIMAS AI Core — первый вертикальный срез

Приоритет задан `MASTER_PROMT.md`. Существующее веб-демо сохранено отдельно.
Движок доступен через CLI и текстовый режим сайта `/?view=ai`.
На главной странице — ссылка «Попробовать AI». Старый видео-сценарий сохранён отдельно.

## Веб-интервью

Создание сессии требует ключ команды. Доступ к сессии защищён отдельным случайным
токеном; в SQLite хранится его хеш, в браузере — токен в sessionStorage.
Состояние, вопросы, ответы и журнал хранятся в новой таблице `ai_sessions`.
Ответ фиксируется до обращения к Groq. Повтор идентичного ответа идемпотентен;
после обрыва обработки доступна повторная отправка сохранённого ответа.
Обновление страницы восстанавливает сессию в той же вкладке. Завершение показывает
evidence-отчёт. Сбой оценщика виден отдельно от отсутствия evidence.
Этот режим текстовый: камера, прокторинг и голос остаются в старом видео-демо.

Локальный API запускается с одним worker. Блокировки сессий в процессе защищают
параллельные запросы этого запуска; несколько worker требуют распределённых блокировок.
В отличие от CLI, состояние веб-интервью восстанавливается из базы после перезапуска.

Версии v2: «не знаю» и явные отказы не порождают отрицательные evidence;
off-topic ответы не превращаются в технические заблуждения. Генератор получает
одну цель и образец вопроса, а не весь перечень понятий. Ограничены длина и число
вопросов; невалидная генерация заменяется вопросом из банка. Журнал оценки сохраняет
категории ошибок и число попыток, не сохраняя сырые ответы API или ключи.

## Что найдено в репозитории

- `backend/app.py`: FastAPI и пять фиксированных этапов, встроенные Groq evaluation/STT.
- `backend/database.py`: SQLAlchemy, SQLite, ответы, события, фрагменты записи.
- `frontend/app/`: Next.js, кабинет, запись интервью и визуальный просмотр.
- `backend/test_*.py`: 9 исходных тестов API и базы, все прошли до изменений.
- `setup.ps1`, `run_demo.py`, `start_demo.bat`: окружение и запуск веб-демо.
- Отдельного AI Engine, планировщика и накопительного evidence-профиля раньше не было.

## Реализованный поток

`CLI → InterviewEngine → QuestionGenerator → AnswerEvaluator → Evidence → Decision → следующий вопрос → JSON report`.

Движок определяет навык, цель, тип и сложность. Модель получает эти значения и генерирует
один вопрос либо структурированную оценку. Она не управляет переходами состояний.

### Состояния

`CREATED → INTRO → SELECT_SKILL → ASK_QUESTION → WAITING_FOR_ANSWER → EVALUATE_ANSWER → DECIDE_NEXT_ACTION`.

Далее `FOLLOW_UP`, `NEXT_QUESTION`, `NEXT_SKILL` или `FINAL_REVIEW → COMPLETED`.
Verification — тип вопроса внутри состояния FOLLOW_UP. Неверный переход,
повторный старт или ответ не на текущий вопрос отклоняются.

### Evidence и оценка

Оценка содержит correctness, depth, demonstrated/missing concepts, misconceptions,
evidence, цель уточнения и результат проверки конкретного заблуждения.
Все критические ответы LLM проходят Pydantic. Цитаты должны точно входить в текущий ответ.
Неподтверждённая цитата отклоняет всю оценку. После двух сбоев ответ сохраняется
с `evaluation.status=unavailable`; вымышленных оценок нет.

SkillEvidence связывает claim и quote с question_id, skill, source, type и временем.
Заблуждение хранит исходный вопрос, статус unresolved/resolved/confirmed и вопрос проверки.
Проверка наличия цитат не доказывает правильность интерпретации LLM — нужна экспертная валидация.

### Детерминированные правила v1

1. Общий лимит вопросов/времени завершает интервью.
2. Лимит вопросов на навык переводит к следующему навыку.
3. Неразрешённое заблуждение вызывает verification; конкретная неопределённость — follow-up.
4. Уточнения ограничены двумя на исходный вопрос; затем берётся следующая цель.
5. Evidence считается по разным вопросам, а не по числу пунктов от модели.
6. Сильный корректный ответ повышает сложность на один шаг; неверный/неопределённый снижает.
7. Рекомендация сложности от модели сохраняется, но не управляет этим правилом.

По умолчанию: максимум 20 вопросов, 4 на навык, 2 уточнения на исходный вопрос, 20 минут.
Сервер завершает интервью через 20 минут после начала даже при закрытой вкладке. Уже сохранённый,
но ещё не оценённый ответ остаётся в отчёте с пометкой «не оценено»; дополнительный вызов AI
для завершения не требуется. Запись видео может загружаться отдельно, текстовый отчёт доступен
сразу после завершения. Сетевой запрос имеет отдельный timeout.
Банк пока содержит по две основные цели на навык: offline-прохождение — 14 вопросов.
Целевые значения 3 для некоторых навыков зарезервированы; до расширения банка повторов нет.

### Отчёт

Нет общего числового score или hire/reject. По запросу пользователя добавлен балл
за отдельный ответ 0–5 (`answer_points_v1`): он детерминированно рассчитывается по
корректности и глубине из оценки AI. В отчёте доступна полная шкала и объяснение.
Корректно: 3/4/5 за низкую/среднюю/высокую глубину; частично верно: 1/2/3;
технически неверно: 0. Пробелы/противоречия ограничивают корректный ответ тремя баллами.
Отказ, ответ не по теме, недостаток evidence, неподтверждённые цитаты или сбой —
`points=null`, а не ноль. Баллы не сравнивают сложность разных вопросов и не являются
общим рейтингом кандидата. Новый разбор доступен и для сохранённых веб-сессий без
повторного вызова модели. Исторические JSON-файлы CLI сами не перезаписываются.
По каждому навыку сохранены evidence,
strengths, gaps, missing concepts и misconceptions. Непроверенные навыки видны явно.
`demonstrated_level` по умолчанию null. Предварительный уровень возможен только после
двух разных целей с корректными глубокими ответами, без отрицательных evidence,
пробелов в этих ответах и неразрешённых заблуждений. Он ограничен целевым уровнем.
Резервные вопросы не используются для вывода уровня: их сложность не калибрована.
Старая отрицательная evidence остаётся даже после исправления заблуждения;
это консервативное ограничение первой версии, а не утверждение о неспособности кандидата.
Правило агрегации экспериментальное и требует калибровки; весь профиль не считается проверенным.

## Запуск

Из корня проекта в существующем окружении:

```powershell
.\.venv\Scripts\python.exe -m cli.main
```

Для CLI без установки фронтенда достаточно зависимостей `ai_core/requirements.txt`.
По умолчанию API не вызывается: вопросы берутся из банка, оценки недоступны.
Введите `/stop` для досрочного завершения. Без персональных данных — только тестовые ответы.

Для живой модели задайте `GROQ_API_KEY` и `GROQ_MODEL` в окружении или локальном `.env`:

```powershell
.\.venv\Scripts\python.exe -m cli.main --live --level middle
```

CLI не выбирает модель, не покупает тариф и не обещает бесплатность любого аккаунта.
Используется GROQ_MODEL; при пустом значении — openai/gpt-oss-120b.
Источник: https://console.groq.com/docs/quickstart . Доступность и квоты зависят от аккаунта.
Перед интервью выполняется один короткий JSON-запрос: ошибка ключа или лимита
останавливает запуск с понятным сообщением. Отдельная проверка:
`python -m cli.main --check-groq`. Запуск двойным щелчком: `start_ai.bat`.
Реальные вызовы в этой реализации не проверялись; ключи не нужны для тестов.

Результаты: `data/ai-core/<уникальный-id>/report.json`, `state.json`, `trace.jsonl`.
Trace записывается после каждого события, включая получение ответа до оценки;
он содержит текст тестовых ответов. При Ctrl+C остаётся trace, финального отчёта может не быть.
Возобновление интервью из state/trace пока не реализовано. `data/` исключена из Git.

## Проверки и следующие шаги

```powershell
.\.venv\Scripts\python.exe -m pytest ai_core/tests backend -q
```

Проверки покрывают неправильный JSON, неподтверждённые цитаты, сбой API, лимиты,
состояния, изменение сложности, verification, отчёт и фактический запуск CLI.
Четыре golden-сценария — вручную заданные ответы и оценки для проверки политики.
Они НЕ измеряют способность реальной модели отличать сильного кандидата от слабого.

Дальше: расширить банк целей и рубрики, отдельно прогнать живой оценщик на golden-ответах,
проверить 5–10 интервью с опытным Python-разработчиком, откалибровать уровни и разрешение
противоречий, затем подключать движок к веб-демо. Критерий доверенного AI Core ещё не достигнут.
