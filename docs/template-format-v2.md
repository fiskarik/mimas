# Формат шаблона интервью v2

Формат v2 переводит шаблон интервью на карточки вопросов: у каждого вопроса есть тип, равноценные формулировки, утверждённые уточнения, описания ответов на 5, 3 и 1 балл, красные флаги и список того, что не оценивается. Обоснование — в `docs/research/interview-templates.md`.

По формату v2 написаны общие шаблоны четырёх розничных профессий: `backend/professions/cashier.json`, `sales_associate.json`, `order_picker.json`, `stock_worker.json`. Шаблоны вакансий, которые генерирует AI, пока остаются в формате v1 (см. «Совместимость»).

## Файл шаблона профессии

```json
{
  "id": "cashier",
  "name": "Продавец-кассир",
  "description": "Короткое описание для выбора профессии",
  "version": 2,
  "settings": {"max_questions": 7, "max_follow_ups": 1, "duration_minutes": 10},
  "not_assessed": ["Акцент и произношение", "Длина ответа"],
  "skills": [
    {"id": "cashier.checkout", "name": "Точность расчёта на кассе",
     "concepts": ["Расхождение цены"], "cards": [{ "...": "карточка вопроса" }]}
  ]
}
```

- `not_assessed` на уровне шаблона — то, что не влияет ни на один балл. Оценщик получает этот список вместе со списком карточки.
- `settings.max_questions` считает и основные вопросы, и уточнения. Значение должно быть не меньше числа карточек: уточнения задаются только из оставшегося запаса (см. «Как идёт интервью»).
- Роль и версия плана (`profession-<id>-v<version>`) подставляются из `name`, `id` и `version`.

## Карточка вопроса

| Поле | Обязательно | Что это |
|---|---|---|
| `goal` | да | Что проверяет вопрос. Это граница оценки: оценщик не требует ничего сверх неё |
| `type` | да | `situational` — «что вы сделаете, если…»; `behavioral` — случай из прошлого (STAR); `knowledge` — знание правила |
| `question` | да | Основная формулировка, до 600 символов |
| `variants` | нет, до 4 | Равноценные формулировки той же ситуации, до 600 символов |
| `probes` | нет, до 3 | Единственные уточнения, которые можно задать по этой карточке |
| `anchors.strong` | да | Описание ответа на 5 баллов |
| `anchors.acceptable` | да | Описание ответа на 3 балла |
| `anchors.weak` | да | Описание ответа на 1 балл |
| `red_flags` | нет, до 4 | Недопустимые действия; ограничивают балл и показываются работодателю |
| `not_assessed` | нет, до 6 | Дополнительно к списку шаблона: что не оценивать в этом вопросе |
| `source` | нет | Откуда взята ситуация: случай управляющего, стандарт сети, закон |

У компетенции в v2 есть только `id`, `name`, `concepts` и `cards`. Поля v1 (`goals`, `questions`, `evaluation_criteria`, `target_questions`) выводятся из карточек автоматически, поэтому старые потребители плана продолжают работать. Смешивать в одном плане компетенции с карточками и без них нельзя.

## Как идёт интервью

1. **Формулировка.** Для каждой карточки движок выбирает основную формулировку или вариант. Выбор зависит от идентификатора интервью: при повторе или восстановлении интервью формулировка та же, а между разными кандидатами варианты чередуются. Номер варианта сохраняется в вопросе (`variant`, 0 — основная формулировка), чтобы потом сравнивать варианты между собой.
2. **Вопросы задаются дословно.** Ни основной вопрос, ни уточнение модель не пишет и не перефразирует.
3. **Уточнение выбирает оценщик:** он указывает номер подходящего вопроса из `probes`, если в ответе не хватает важной части описаний. Свободные уточнения, проверки противоречий и заблуждений в v2 не задаются.
4. **Уточнения не вытесняют карточки.** Уточнение задаётся, только если после него ещё хватит лимита `max_questions` на все оставшиеся карточки. При 5 карточках и лимите 7 бывает не больше двух уточнений, и все пять основных вопросов гарантированно прозвучат. Остановить интервью раньше может только лимит времени.
5. **Вопрос об опыте (`behavioral`).** Оценщик отмечает, есть ли в ответе реальная ситуация, собственные действия и результат (STAR). Если нет ситуации или личных действий, ответ не оценивается. Уточнение в этом случае спрашивает недостающее.

## Как ставятся баллы

- **Балл за ответ.** Оценщик сравнивает действия в ответе с описаниями и ставит 5, 3 или 1; 4 и 2 — промежуточные оценки. Уровень обязательно подтверждается точными цитатами из ответа.
- **Красный флаг** засчитывается только с цитатой, где кандидат сам называет это действие. Флаг ограничивает балл двумя.
- **Не оценено.** Отказ, ответ не по теме, ответ на вопрос об опыте без реального случая и сбой AI — это «не оценено», а не ноль.
- **Балл вопроса** — лучший из основного ответа и ответа на уточнение. Уточнение оценивается вместе с исходным ответом, а красный флаг в любом из них ограничивает итог. Итоги по вопросам лежат в `report.card_scores`.
- **Балл компетенции** — среднее по её вопросам (`report.skills[].score`). Предварительный рейтинг для работодателя — среднее по всем оценённым вопросам.

## Как писать карточку

- **Варианты** — та же ситуация той же сложности, и они просят те же элементы ответа. Если основной вопрос спрашивает «…и что скажете покупателю?», варианты спрашивают то же самое, иначе кандидаты получат неравные условия.
- **Описания ответов** — наблюдаемые действия («сверяет код товара с заказом»), а не качества («внимательный»). Конкретный порядок действий заменяется словами «по правилам магазина»: кандидат не обязан знать стандарт конкретной сети.
- **Красный флаг** — действие, которое кандидат может сам назвать в ответе на этот вопрос. Флаг не может следовать из того, что кандидат чего-то не упомянул.
- **Уточнение** — короткий вопрос об одной недостающей части ответа, без подсказки правильного ответа.
- **Что не оценивать.** В `not_assessed` попадает всё, что кандидат не обязан знать или что не связано с работой: названия документов и программ, номера законов, акцент, грамотность.
- **Запрещённые темы.** Не спрашивать о семье, детях, беременности, национальности, религии, месте жительства и здоровье сверх требований к должности (ст. 3 и 64 ТК РФ).

## Совместимость и обновление

- **Старые интервью** хранят снимок своего плана и дочитываются как раньше. Отчёты v1 не меняются.
- **Шаблоны вакансий** генерирует AI по схеме v1 (`plan_json_schema()` без карточек). Перевести их на v2 — отдельная задача: нужны генерация карточек и редактор описаний ответов в кабинете работодателя.
- **Обновление профессий в базе.** При старте `ensure_professions` ставит недостающие профессии. Строку предыдущей версии он заменяет новой, только если её текст совпадает с отпечатком из `_PRISTINE_FINGERPRINTS`. Строки, которые правил рецензент, остаются как есть.
- **Как выпустить новую версию шаблона** (например, v3):
  1. Увеличьте `version` в JSON.
  2. Добавьте в `_PRISTINE_FINGERPRINTS` отпечаток текущей версии v2 для каждой изменённой профессии. Его считает `_fingerprint()` по строке, установленной текущим кодом. Тест `test_each_catalog_version_keeps_an_upgrade_path_for_unedited_rows` не даст забыть этот шаг.
- **Точное содержимое строк v1** для тестов обновления лежит в `backend/fixtures/retail_professions_v1.json`.

## Что не сделано

- Эталонные ответы и замер точности оценки по новым шаблонам.
- Формат v2 для шаблонов вакансий и редактор карточек у работодателя.
- Стоп-вопросы, честное описание работы и разминочный вопрос перед голосовым этапом (`docs/research/interview-templates.md`, раздел 6).
- Живая проверка на Yandex: тесты используют подставную модель.
