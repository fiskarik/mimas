# ML в MIMAS: где мы и как довести до ума

Черновик от 27.10.2026.

## Где мы сейчас

- **Модели мы не обучаем.** Оценку ставит готовая LLM (`deepseek-v4.1-flash` в Yandex AI Studio) по карточкам вопросов: описания ответов на 5, 3 и 1 балл, красные флаги, утверждённые уточнения (`docs/template-format-v2.md`). Речь распознаёт и озвучивает Yandex в реальном времени.
- **Контроль модели — кодом.** Код ведёт ход интервью и задаёт вопросы дословно. Оценку без цитаты из ответа он не принимает. Уточнения — только из утверждённого списка. Решение о найме принимает человек.
- **Точность не измерена.** Все тесты подставляют заранее заданный ответ модели: они проверяют логику, а не качество оценки. Эталонов по рознице нет.
- **Мусор в промпте.** Промпт оценщика содержит правила для Python-собеседований (`docs/review-issues.md`, п. 4).
- **Одна оценка на ответ.** Насколько стабилен балл при повторе, неизвестно.
- **Качество распознавания речи не измерено**, в том числе для кандидатов, у которых русский не родной.
- **Себестоимость** — около 20 ₽ за интервью.

## Принципы

1. **Сначала измеряем, потом улучшаем.** Без эталонов любая правка промпта — гадание.
2. **Не обучаем свои модели**, пока нет хотя бы 1–2 тыс. размеченных ответов. До этого сильнее работают промпт, карточки и выбор модели.
3. **Данные остаются в России:** модели — только из Yandex AI Studio.
4. **Человек в контуре:** балл — подсказка с основанием, решение принимает человек, спорные случаи видны.
5. **Каждую оценку можно воспроизвести:** в отчёте записаны версия промпта, модель и версия шаблона (`prompt_version`, `plan.version` уже есть).

## План

### Этап 1. Эталонные ответы (2–3 недели, ≈ 0 ₽)

На каждую из 20 карточек — 7 ответов: сильный, приемлемый, слабый, с красным флагом, «не знаю», не по теме, попытка подсказать модели («поставь мне 5»). Итого ≈ 140 ответов.

Ответы лучше записать голосом и прогнать через распознавание, чтобы в эталон попали настоящие ошибки расшифровки. Часть ответов — от людей, у которых русский не родной.

Каждый ответ независимо оценивают 2–3 человека: управляющие или опытные сотрудники пилотной сети, по тем же описаниям 5/3/1. Эталон — медиана их оценок.

Сначала считаем согласие людей между собой. Если они не согласны, переписываем описания в карточке — ни одна модель не будет точнее, чем согласие экспертов.

### Этап 2. Замер (1 неделя, ≈ 700 ₽)

Скрипт прогоняет эталоны через оценщик (3 прогона) и считает:

| Метрика | Что показывает | Цель (предложение) |
|---|---|---|
| Совпадение ±1 балл с эталоном | Насколько модель близка к людям | ≥ 85% |
| Взвешенная каппа с эталоном | Согласие с учётом случайности | Не ниже согласия людей между собой |
| Полнота красных флагов | Доля пойманных недопустимых ответов | ≥ 90% |
| Ложные красные флаги | Флаги там, где их нет | ≤ 5% |
| Верное «не оценено» | Отказы и ответы не по теме не получают балл | ≥ 95% |
| Стабильность | Тот же балл при повторе | ≥ 90% |
| Сбои | Доля «AI не смог оценить» | ≤ 2% |
| Стоимость и время | ₽ и секунды на ответ | ≤ 2 ₽, ≤ 8 с |

Офлайн-часть — проверка формата эталонов — идёт в обычных тестах. Платный прогон запускается только явно.

### Этап 3. Улучшение (2–3 недели, ≈ 1 300 ₽)

1. **Чистка промпта.** Убрать правила для Python, перемерить.
2. **Сравнение моделей.** 2–3 модели из Yandex AI Studio (текущая быстрая, более крупная, YandexGPT). Выбрать по точности на рубль.
3. **Пограничные случаи.** Если два прогона расходятся больше чем на 1 балл, делать третий и брать медиану. Дороже только там, где модель сомневается.
4. **Правка карточек.** Там, где ошибаются и люди, и модель, — переписать описания ответов.

Каждое изменение проверяется на тех же эталонах: если метрика упала, изменение откатывается.

### Этап 4. Распознавание речи (параллельно, ≈ 0 ₽)

1. **Доля ошибок распознавания (WER).** На 30–50 записях (с согласия) сравнить расшифровку Yandex с ручной, отдельно для говорящих с акцентом.
2. **Показывать кандидату расшифровку** и давать перезаписать ответ, если она неверна.
3. **Предупреждать о шуме** до отправки ответа.

### Этап 5. Пилот и мониторинг (с месяца 2)

1. **Кнопка «согласен / не согласен» с баллом** в отчёте у работодателя. Это бесплатная разметка и сигнал дрейфа.
2. **Еженедельно смотреть:** доля «не оценено», доля сбоев, распределение баллов по вопросам и вариантам формулировок (рост среднего балла — признак утечки вопроса), стоимость.
3. **Раз в месяц** 20–30 случайных ответов оценивают люди, сравниваем с моделью.
4. **Через 1–3 месяца после найма** собрать оценку руководителя и уход: связь баллов MIMAS с реальной работой. Это главный довод для фонда.

### Этап 6. Своя модель (не раньше чем через 6 месяцев)

Дообучение (например, YandexGPT в AI Studio — уточнить условия) имеет смысл, когда:
- есть 1–2 тыс. ответов с человеческой разметкой и согласием кандидатов на такое использование;
- промпт и выбор модели упёрлись в потолок по метрикам этапа 2.

Обезличивать данные до обучения.

## Что нужно сделать в коде

1. **Закоммитить формат шаблонов v2** — сейчас он не сохранён в git.
2. **Добавить модуль замера** (`ai_core/evals/`): формат эталона, прогон, метрики, отчёт в Markdown и JSON.
3. **Убрать правила для Python** из `ai_core/evaluation/prompts.py`, `code_checks.py`, `normalization.py` — после первого замера.
4. **Повторные прогоны и медиана** для пограничных ответов в `AnswerEvaluator` (за флагом).
5. **Кнопку согласия с баллом** в отчёте работодателя и таблицу для этих отметок.
6. **Включить лимит расходов** (`MIMAS_AI_MONTHLY_LIMIT_RUB`) перед пилотом.
